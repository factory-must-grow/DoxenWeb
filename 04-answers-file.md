# 04 — Файл ответов

JSON-файл со значениями переменных. Пользователь скачивает его после
заполнения и загружает в следующий раз, чтобы не вводить всё заново.
Файл принадлежит пользователю и на сервере не хранится.

## Структура

**На верхнем уровне — общие значения и массив наборов данных.**

```json
{
  "doxenVersion": 1,
  "shared": {
    "org": {
      "name": "ООО «Рога и копыта»",
      "inn": "7701234567",
      "bank": { "bankName": "ПАО «Сбербанк»", "bik": "044525225" },
      "director": {
        "firstName": "Иван", "middleName": "Петрович", "lastName": "Сидоров"
      }
    }
  },
  "datasets": [
    {
      "title": "Кузнецова М. А.",
      "values": {
        "agent": { "fullName": "Кузнецова Мария Алексеевна", "passport": "45 11 654321" },
        "doc":   { "number": "14/2026", "validUntil": "31 декабря 2026 г." }
      }
    },
    {
      "title": "Петров С. И.",
      "values": {
        "agent": { "fullName": "Петров Сергей Иванович", "passport": "45 09 112233" },
        "doc":   { "number": "15/2026", "validUntil": "31 декабря 2026 г." }
      }
    }
  ]
}
```

### Почему `datasets`, а не `documents`

Один элемент массива — это **набор данных**, а не документ. Сколько из
него получится файлов, зависит от числа загруженных шаблонов: сейчас
шаблон один, значит один набор даёт один документ; когда появится
загрузка нескольких шаблонов, тот же набор даст по документу на каждый.

Файл предназначен для правки руками, поэтому имя должно быть честным.

### Две оси генерации

Документы получаются перемножением двух независимых осей:

| Ось | Что меняется | Где задаётся |
|---|---|---|
| «для кого» | контрагент, представитель, объект | элементы `datasets[]` |
| «что именно» | договор, акт, доверенность | выбор шаблонов в интерфейсе |

Три шаблона и десять наборов дают тридцать документов.

**Сейчас реализуется только первая ось**: шаблон загружается один,
вторая ось всегда равна единице. Формат при этом уже готов ко второй,
и файлы, сохранённые сейчас, продолжат работать без правки.

### Имя шаблона в файле ответов не хранится

Принципиальное решение: **выбор шаблонов — целиком дело интерфейса.**
В JSON нет и не будет поля с именем шаблона.

Причина: файл ответов описывает клиента, а не то, какие бумаги
оформляются сегодня. Один и тот же файл с реквизитами ООО сегодня идёт
на доверенность, завтра на договор. Имя файла шаблона внутри JSON
сделало бы файл одноразовым и ломало бы его при переименовании
`Доверенность.docx` в `Доверенность 2026.docx`.

Следствие: **каждый набор применяется ко всем выбранным шаблонам.**
На практике это работает, потому что разные документы используют
разные переменные — договор берёт `contract.number`, акт `act.number`,
и оба значения спокойно лежат в одном наборе, каждый шаблон подставляет
своё.

Единственный проблемный случай — два шаблона используют **одинаковый
путь с разным смыслом**: оба написали `doc.number`, но номера нужны
разные. Решается переименованием переменной в одном из шаблонов.
Специального механизма переопределений под шаблон в формате нет
намеренно: одинаковое имя для разных вещей — это проблема самих
шаблонов, и лечить её надо там, а не обходить в формате данных.

### Порядок разрешения значения

Для каждой переменной шаблона при сборке документа из набора `i`:

1. искать путь в `datasets[i].values`;
2. если не нашлось — искать в `shared`;
3. если не нашлось нигде — это недостающее значение, спросить у
   пользователя.

Поиск ведётся **по полному пути**, а не по первому сегменту: если в
`shared` есть `org.name`, а в `values` набора — `org.inn`, то
разрешатся оба. Слияние происходит на уровне листьев, а не целых веток.

Смысл разделения: в пакете «доверенность на десять человек»
организация, директор и банк одинаковы для всех, а ФИО и паспорт
представителя свои у каждого. Повторять блок `org` десять раз — мусор
и источник рассогласования: поправят в одном месте, забудут в девяти.

Из этой же структуры естественно следует интерфейс: `shared` —
обычная форма сверху, `datasets` — таблица снизу, строка на набор
(см. `05-screens.md`).

### Одиночный документ

Тот же формат с одним набором. `shared` можно не заполнять вовсе —
тогда все значения лежат в `datasets[0].values`. Оба варианта
допустимы, Doxen при записи файла раскладывает значения по правилу:
что вводилось в общей форме — в `shared`, что в таблице — в `values`.

`title` — необязательное человекочитаемое имя набора. Используется как
имя файла в ZIP при пакетной сборке и как подпись строки в таблице.
Если отсутствует — подставить «Документ 1», «Документ 2» и так далее.

`doxenVersion` — версия формата. Сейчас всегда `1`. При чтении: если
поле отсутствует, считать `1`; если больше известной версии — сообщить
пользователю, что файл создан более новой версией Doxen.

### Совместимость при чтении

Принимать без ошибки:

- файл без `shared` — просто первый шаг разрешения всегда промахивается;
- файл, где вместо `datasets` стоит **`documents`** — прочитать как
  `datasets`. Пользователь мог сохранить файл ранней версией или
  списать имя из старой документации;
- файл, где массива нет вовсе, а значения лежат прямо в корне —
  считать его одним набором.

Записывать Doxen всегда должен `datasets`.

## Все значения — строки

В `values` листовые значения хранятся **строками**, ровно так, как они
попадут в документ:

```json
"validUntil": "31 декабря 2026 г."
```

а не `"2026-12-31"` и не объектом с типом. Причина: Doxen не знает и не
должен знать, в каком виде пользователь хочет видеть дату в своём
документе. Что ввели — то и подставится.

Числа и `true`/`false` при чтении допускаются (пользователь мог
поправить файл вручную) и приводятся к строке, но при записи Doxen
всегда пишет строки.

## Определение типа поля ввода — только подсказка интерфейса

Когда значения нет и его надо спросить, форма показывает обычное
текстовое поле. Исключения — эвристика по последнему сегменту пути:

| Признак в имени | Поле ввода |
|---|---|
| содержит `date`, `дата`, `until`, `from`, `till` | выбор даты + флажок «Без даты» |
| содержит `inn`, `kpp`, `ogrn`, `bik`, `count`, `number`, `sum`, `amount` | текстовое поле с числовой клавиатурой |
| путь является аргументом функции ФИО | три поля: имя, отчество, фамилия |
| остальное | обычное текстовое поле |

**Эвристика влияет только на удобство ввода, но не на результат.**
В файл ответов и в документ всё равно уходит строка. Пользователь
должен иметь возможность переключить поле в обычный текст — рядом
ссылка «ввести вручную».

Список признаков вынести в константу в одном месте, чтобы его можно
было дополнять.

## Слияние загруженного файла с формой

При загрузке файла ответов вместе с шаблоном:

1. Разобрать шаблон → список переменных.
2. Для каждой переменной попытаться разрешить путь по `datasets[0].values`.
3. Разрешённые — показать в форме заполненными, **доступными для
   правки**, с пометкой «из файла ответов».
4. Неразрешённые — показать пустыми полями ввода.
5. Значения из файла, которым не соответствует ни одна переменная
   шаблона, **сохранить и записать обратно** в скачиваемый файл ответов.
   Пользователь мог собрать один файл под несколько шаблонов — стирать
   лишнее нельзя.

Пункт 5 важен и легко упускается. Итоговый файл ответов = исходный файл
(если был) + всё, что ввели в форме, с приоритетом у формы.

## Скачивание файла ответов

Отдаётся кнопкой «Скачать файл ответов» на экране заполнения — доступна
и до, и после сборки документа. Имя файла: `имя-шаблона.answers.json`.
Форматировать с отступами (`WriteIndented = true`) — файл предназначен
для правки руками.

Кодировка UTF-8 **без BOM**. Кириллицу не экранировать: при
сериализации задать `Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping`,
иначе русский текст превратится в `\u0420\u043e\u0433\u0430` и станет
нечитаемым при ручной правке.

## Ошибки при чтении

- битый JSON → «Не удалось прочитать файл ответов: ошибка в строке N.
  Проверьте файл в текстовом редакторе.» (номер строки берётся из
  `JsonException.LineNumber`)
- корень не объект или нет `datasets` → «Это не похоже на файл ответов
  Doxen.»
- `datasets` пуст → работать как будто файла нет, без ошибки

Ошибка в файле ответов **не должна ронять весь сценарий** — пользователь
остаётся на экране заполнения, просто с пустыми полями и сообщением.
