# 05 — Экраны и сценарии

Внешний вид всех экранов — по макету `doxen-design.html`.
Здесь описано поведение.

## Карта маршрутов

| Маршрут | Доступ | Назначение |
|---|---|---|
| `/` | все | Главная с демо-разбором шаблона |
| `/generate` | все | Заполнение и сборка (для анонимов — до скачивания) |
| `/account/register` | анонимы | Регистрация |
| `/account/login` | анонимы | Вход |
| `/account/logout` | вошедшие | Выход (только POST) |
| `/account` | вошедшие | Профиль: тариф, расход за месяц |
| `/admin/users` | админы | Список пользователей |
| `/admin/plans` | админы | Редактирование тарифов |

Всё, что под `/admin`, закрыть политикой авторизации на уровне папки
(`AuthorizeFolder("/Admin", "AdminOnly")`), а не проверками в каждой
странице по отдельности.

## Главная

Демо работает **без регистрации**: пользователь бросает `.docx`, сервер
разбирает и показывает найденные переменные. Это дёшево (только чтение)
и снимает главное возражение «а оно поймёт мой шаблон?».

Ограничения для анонимов на разбор: размер файла — по тарифу `free`,
частота — не чаще 10 разборов в минуту с одного IP (простой счётчик в
`IMemoryCache`, без БД).

После разбора анонимный пользователь попадает на `/generate` и может
заполнить форму. Кнопка «Собрать документ» ведёт на регистрацию с
сохранением введённого в сессии — после регистрации он возвращается
и получает документ, не вводя всё заново. Это важная деталь: терять
заполненную форму при регистрации нельзя.

## Экран заполнения `/generate`

Состояние экрана хранится в сессии: список переменных, введённые
значения, загруженный файл ответов и **ключ** записи кеша с шаблоном.
Сам шаблон лежит в `IMemoryCache` и в сессию не копируется
(см. `01-architecture.md`).

Если запись кеша истекла или была вытеснена, экран сообщает
«Загрузка шаблона устарела. Выберите файл ещё раз» и показывает поле
выбора файла, **сохраняя все уже введённые значения**. Заполнять заново
пользователь не должен.

Слева — форма, справа — предпросмотр. Предпросмотр показывает первые
~40 строк текста документа с подстановкой уже введённых значений;
незаполненные места остаются подсвеченными жёлтым. Обновляется при
уходе фокуса с поля, отдельным лёгким POST-запросом, возвращающим
только фрагмент разметки.

> Если предпросмотр окажется трудоёмким — реализовать его последним,
> он не блокирует основной сценарий. Но в макете он есть, и без него
> экран выглядит пустым справа.

Группировка полей: по первому сегменту пути (`org.*` → группа
«org»). Заголовок группы — сам сегмент, если в файле ответов у объекта
нет ключа `title`. Внутри группы — порядок появления в документе.

Кнопки внизу:
- **Собрать документ** (жёлтая, основная) — генерация и скачивание
- **Скачать файл ответов** — доступна всегда
- Счётчик подстановок справа — справочно

## Пакет: несколько документов за раз

Пакетный режим включается двумя способами: пользователь загрузил файл
ответов, где в `datasets[]` больше одного набора, или сам нажал
«Добавить ещё документ» на экране заполнения.

Экран делится на две части, повторяя структуру файла ответов
(см. `04-answers-file.md`):

**Сверху — «Общее для всех документов».** Обычная форма, как в
одиночном режиме. Сюда попадает то, что одинаково: организация,
директор, банк.

**Снизу — таблица «По каждому документу».** Строка на документ,
столбец на переменную. Первый столбец — `title`, подпись документа.

```
│ Документ            │ agent.fullName          │ agent.passport │ doc.number │
│ Кузнецова М. А.     │ Кузнецова Мария Алекс…  │ 45 11 654321   │ 14/2026    │
│ Петров С. И.        │ Петров Сергей Иванович  │ 45 09 112233   │ 15/2026    │
│ + добавить строку                                                            │
```

Именно таблица, а не десять форм подряд: десять наборов по пятнадцать
полей в виде повторяющихся форм заполнять невозможно, а в виде таблицы —
обычная работа, привычная по Excel.

**Вставка из буфера обмена.** В таблице должна работать вставка
скопированного из Excel диапазона: строки разделены `\n`, ячейки —
табуляцией. Это главный способ, которым реально заполняют десять
доверенностей, и без него таблица теряет смысл.

**Куда отнести переменную.** По умолчанию Doxen раскладывает так:
всё, что нашлось в `shared` загруженного файла — наверх, остальное —
в таблицу. Если файла не было, все переменные попадают наверх, а
пользователь переносит нужные вниз кнопкой «своё для каждого документа»
у поля. Обратный перенос — тоже.

Кнопка внизу — «Собрать документы», на выходе ZIP: файл на набор,
имена из `title`.

Наборы, где не хватает значений, всё равно собираются — с пустотами
на месте недостающего, как и в одиночном режиме. Пользователь решает сам.

Пакетный режим доступен только при `plans.allow_batch = true`. Иначе —
сообщение: «В файле ответов N наборов данных. Сборка нескольких
документов за раз доступна на тарифе «Pro»; на «Free» будет собран
только первый.» И собрать первый, а не отказать целиком.

## Проверка лимитов

Порядок проверок при нажатии «Собрать документ»:

1. **Размер файла** — до разбора. Превышение: «Файл больше N МБ.
   На тарифе «Free» это предел; на «Pro» — M МБ.»
2. **Количество переменных в шаблоне** — после разбора. Превышение:
   «В этом шаблоне N переменных, а на тарифе «Free» можно до M.
   Обычно это значит, что в одном файле собрано много документов
   сразу — разделите их или перейдите на «Pro».» Формулировка должна
   объяснять, а не просто отказывать.
3. **Документов за месяц** — перед генерацией. Превышение: «В этом
   месяце вы собрали все N документов тарифа «Free». Лимит обновится
   1 [следующий месяц] или можно перейти на «Pro».»

   При пакете считается **весь пакет целиком**: десять наборов — это
   десять документов против месячного лимита. Если до лимита осталось
   меньше, чем наборов в пакете, не собирать частично: сказать заранее
   «В пакете 10 документов, а до конца лимита осталось 3» и дать
   пользователю решить.

Счётчик инкрементируется **только при успешной генерации**, одной
атомарной операцией (см. `02-database.md`). При пакете инкремент
на число **успешно собранных** документов, а не на размер пакета:
за неудавшиеся элементы платить не должны.

Для анонимов проверки 1 и 2 выполняются по тарифу `free`; проверка 3
не выполняется, так как без регистрации документ всё равно не скачать.

## Админка

**`/admin/users`** — таблица: почта, тариф (выпадающий список,
меняется на месте), документов за текущий месяц, дата регистрации,
признак блокировки. Пагинация по 50, поиск по почте. Смена тарифа
пишется сразу, без отдельной кнопки «Сохранить» на всю страницу.

**`/admin/plans`** — редактирование тарифов: название, цена, три
числа лимитов, `allow_batch`, активность. Добавление нового тарифа.
Удаление тарифа, к которому привязаны пользователи, запрещено —
предложить сначала перевести их.

Первый администратор создаётся миграцией или командой запуска
(email и пароль из переменных окружения при первом старте),
а не через интерфейс регистрации.

## Тон сообщений

Ошибка объясняет, что случилось и что делать. Не извиняется, не
использует технические термины. Пустой экран — это приглашение
к действию, а не сообщение о пустоте.

Плохо: «Ошибка валидации. Поле обязательно.»
Хорошо: «Укажите ИНН — он подставляется в документ в трёх местах.»

Плохо: «Файл не найден.»
Хорошо: «Шаблон не загрузился. Выберите файл ещё раз.»
